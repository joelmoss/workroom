```swift
func addProject(_ path: String, create: Bool) async -> Result<Void, Error> {
  // Fixture mode never shells out to the real CLI for anything else (`bootstrap`/`load` both
  // short-circuit to `loadFixture()`) — this is the one mutation that didn't follow that rule,
  // which meant a UI test driving the wizard's real Add Project step (issue #151) genuinely
  // registered a project in the developer's own `~/.config/workroom/config.json` (the CLI has no
  // config-path override to isolate against instead). Simulate the same success shape locally.
  if UITestFixture.isActive {
    let canonical = AddProjectSheetModel.normalize(path)
    if !projects.contains(where: { $0.path == canonical }) {
      projects.append(Project(path: canonical, vcs: "git", workrooms: []))
    }
    selectedProjectID = canonical
    selectedTargetID = .root(project: canonical)
    return .success(())
  }
  do {
    let canonical = try await cli.addProject(path, create: create)
    await reload()
    if let match = projects.first(where: { $0.path == canonical }) {
      selectedProjectID = match.id
      selectedTargetID = .root(project: match.path)
    }
    return .success(())
  } catch {
    present(error)
    return .failure(error)
  }
}
```

```swift
private var splitView: some View {
  // [existing large comment block about NavigationSplitView/detail-only choice]
  // The inspector has nothing to show without a selected target (its panes all render a "Select a
  // workroom…" placeholder instead), so it's also gated on that — not just the user's `showInspector`
  // toggle — closing itself whenever nothing's open instead of sitting there empty. A pure view-layer
  // gate, not a write to `Defaults[.showInspector]`: that key is shared across every window, so
  // flipping it here would also close the inspector in any OTHER window that still has something
  // selected. The toggle's own on/off state (View menu, `ActivityBar`) is untouched either way — it
  // just resumes controlling real visibility again the moment something's selected.
  let inspectorVisible = showInspector && store.selectedTarget != nil
  return NavigationSplitView(columnVisibility: .constant(.detailOnly)) {
    Color.clear.frame(width: 0)
  } detail: {
    HStack(spacing: 0) {
      if store.sidebarVisible {
        SidebarColumn(...)
          .transition(.move(edge: .leading))
      }
      detail
        .frame(maxWidth: .infinity, maxHeight: .infinity)
      if inspectorVisible {
        InspectorColumn()
          .transition(.move(edge: .trailing))
      }
      ActivityBar()
    }
    .animation(reduceMotion ? nil : .easeInOut(duration: 0.2), value: store.sidebarVisible)
    .animation(reduceMotion ? nil : .easeInOut(duration: 0.2), value: inspectorVisible)
  }
}
```
Hit a compile error on first attempt: "function declares an opaque return type, but has no return statements in its body from which to infer an underlying type" — the `let inspectorVisible = ...` statement before `NavigationSplitView(...)` (previously the property's sole/final expression) meant the property was no longer a single-expression implicit-return body. ## 4. Errors and Fixes

1. **SceneBuilder doesn't support if/else between Scene values** — compile error: "closure containing control flow statement cannot be used with result builder 'SceneBuilder'". Fixed by reverting to an unconditional `Window` scene declaration (accepted as a documented limitation per user's "leave this" directive).

2. **`.accessibilityIdentifier` on SwiftUI content doesn't reach the NSWindow chrome** — `XCUIApplication.windows[identifier]` queries the NSWindow's own AX identifier, not the content's. Fixed by calling `window.setAccessibilityIdentifier("onboarding.window")` directly in the `WindowAccessor` callback.

3. **Ambiguous radio-button matcher in UI test** — `app.radioButtons.element(matching: NSPredicate(...))` matched multiple elements. Fixed with a direct exact-string lookup: `window.radioButtons["Create new directory…"]`.

4. **UI test leaked into real `~/.config/workroom/config.json`** — user explicitly corrected: "tests should never use the real config." Root-caused by making `AppStore.addProject` check `UITestFixture.isActive` and simulate success locally, matching the pattern every other mutation already followed. This obsoleted an earlier, more complex workaround (external `defaults` shell-outs, HOME-env isolation attempts) that I had built and then removed.

5. **`orderOut(nil)` in WindowAccessor doesn't reliably hide the main window** — user provided a screenshot proving "main window is still visible" despite the order-out call. SwiftUI's own `WindowGroup` launch machinery re-asserts window visibility after the callback runs. Fixed by switching to the proper `.defaultLaunchBehavior(.suppressed/.presented)` SwiftUI API on both scenes.

6. **Regression from the `.defaultLaunchBehavior` fix**: `handleAdd()`'s `WindowRegistry.shared.lastActiveStore` was `nil` because the main window no longer exists at launch time (it's suppressed). Discovered when user said "rerun the UI tests" and `testAddingAProjectAdvancesToDone` failed with "should auto-advance to Done." Fixed by falling back to a throwaway `AppStore(projectStore: .shared)` when no registered window exists.

7. **XCUITest "Timed out while enabling automation mode"** — recurring wedge from repeated manual AppleScript/System Events driving within the same session. Not a code bug; retried once each time, then stopped looping and either did manual visual verification instead or reported the wedge status to the user rather than continuing to retry.

8. **Compile error: "function declares an opaque return type, but has no return statements"** — introduced a `let` binding before the final expression in `splitView`'s computed property body, breaking Swift's implicit single-expression return inference. Fixed by adding explicit `return` before `NavigationSplitView(...)`.

9. **Blurry upscaled icon** — `MenuBarIcon.imageset` only has 18px/36px PNG sources; scaling to 128px in `RootView` produced visible blur. User reported: "the logo on that screen is bad quality." Root-caused by finding the icon is actually vector-rendered (`renderMenuBarGlyph` in `Scripts/make-icon.swift`, drawing `markBlocks` at any given pixel size) rather than a fixed bitmap — so the fix was to render a proper high-res version (`AppMark.imageset`, 128/256px) using the same function, not to just resize the existing low-res asset.
