## 3. ONE piece of state or TWO?

**ONE**, for sidebar-row selection vs detail-pane content. There is no `selectedFile`, no `selectedCommit`, no `detailSelection` anywhere in the app. The sidebar row's selected-ness is a pure projection of `TerminalSessions.focusedTabByTarget[target] → tabsByTarget[target][id].content` through `FocusedTabSelection.current`. You cannot desynchronise them, and there is no "sidebar selection" to clear.

Things that *are* separate, independent state (and worth not confusing with the above):

1. **Which sidebar panel is shown** — `AppStore.activeInspectorSection: ActivitySection` (`AppStore.swift:439`, `@Published`, persisted to `Defaults[.activeInspectorSection]` in `didSet`). `ActivitySection` is only `.changes | .files` (`Core/ActivitySection.swift:15-19`); `.changes.subSections == [.changes, .history, .pullRequest]` (`:42-47`). Read by `RightInspector.body` at `Views/ChangesPanel.swift:25`. Pane visibility is a *third*, separate flag: `Defaults[.showInspector]` via `AppStore.inspectorIsVisible` (`AppStore.swift:474`). Reduced by the pure `ActivityBarReducer` (`Core/ActivityBarReducer.swift:15`) with three distinct actions. Collapse flags are yet more separate state: `changesSectionCollapsed` `:321`, `prSectionCollapsed` `:328`, `historySectionCollapsed` `:333`, plus `inspectorSizeWeights: [Double]` `:432`.
2. **Which workroom the detail pane shows** — `AppStore.selectedTargetID: SidebarID?` (`AppStore.swift:156`, `@Published`, big `didSet`). Orthogonal to which tab is focused within it; the inspector follows `inspectorTargetID` (`:1013`) which is `selectionHasTabs ? selectedTargetID : nil`.
3. **The file selected *inside* a changeset tab** — `ChangesetDescriptor.selectedPath` (`ChangesetDescriptor.swift:22`), stored **on the tab**, not on the sidebar. `ChangesetDetailView.selectedPath` (`Views/ChangesetDetailView.swift:28`) reads the descriptor and falls back to `changeset.files.first?.path`; the tap routes through `store.selectChangesetFile` (`ChangesetDetailView.swift:311`) → `terminals.setChangesetSelectedPath` (`TerminalSessions.swift:518`), explicitly *not* view-local `@State` (comment at `ChangesetDetailView.swift:11-13`) so back/forward can restore it. Its inner diff is a `DiffViewer` with a synthesized `DiffSource.commit(descriptor.commitID)` (`ChangesetDetailView.swift:358-361`).
4. **Per-tab view overrides** — `TerminalTab.diffViewModeOverride: DiffViewMode?` (`TerminalSessions.swift:22`) and `markdownPreviewOverride: Bool?` (`:27`), set by the tab toolbar, read at `PaneTreeView.swift:514` / `:528`.

### Back/forward history is the one place that *duplicates* the selection

`Core/NavigationHistory.swift:7` `struct NavLocation { target: SidebarID; tab: TerminalTab.ID; commitID: String?; commitTitle: String?; filePath: String? }`. The `commitID`/`filePath` fields are a **snapshot copy**, needed because a *preview* tab is retargeted in place across commits (same `TerminalTab.ID`), so `(target, tab)` alone is not a stable location. Built by `AppStore.location(target:tab:)` (`AppStore.swift:3671`), recorded by `recordCurrentLocation()` (`:3660`), replayed by `applyLocation(_:recordHistory:)` (`:3721`) which re-opens the recorded commit when the focused tab has drifted (`:3727-3739`). Guarded throughout by `isNavigatingHistory`.
