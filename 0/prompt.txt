**Answer: Dev servers (run commands) are ALWAYS stopped on quit, regardless of `backgroundSessions` setting.**

**Why:**
1. Run commands use supervisor.sh as a PTY child of libghostty (not daemon-backed). Line 1809-1811 in AppStore.swift: "supervisor becomes the session-leader PTY child."
2. TerminalPersistentSessionPolicy (line 12) excludes run commands from persistent-session eligibility: `!isRunCommand &amp;&amp; …`
3. `gracefullyStopAllWindows` (line 704-708 in WorkroomApp.swift) is called **unconditionally** if any run command exists, regardless of backgroundSessions value.
4. Plain shell terminals differ: they're daemon-backed and survive quit only when backgroundSessions=ON (line 686-693).

**The alert message is misleading:** When backgroundSessions=ON, it says "Quitting leaves background terminals running," but run commands stop anyway.</result>
