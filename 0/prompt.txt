### 1. FIXABLE — the eager `focus` is now a real VCS read fired in the *default* configuration, with the inspector closed, undebounced, on an uncancellable dispatch

This is the finding that matters. Four call sites moved from `activeInspectorSection == .history` to `historySectionShown`:

`AppStore.swift:322-324`
```swift

  activeInspectorSection.subSections.contains(.history) &amp;&amp; !historySectionCollapsed

```

Both conjuncts are true for the **shipped defaults** (`.changes` is the key default; `historySectionCollapsed = false`; and §3 below guarantees every upgrading user lands there). The old gate was a deliberate minority state — a user who had clicked the History icon in the rail. So `AppStore.swift:175` and `AppStore.swift:774` now fire for essentially everyone, on every selection change and every tab open/close.

The justification for skipping the visibility gate is factually wrong. `AppStore.swift:319-321`:
```
/// swapped-out section must not run VCS reads for a log nobody can see. Deliberately NOT gated on
/// `inspectorIsVisible`: the visibility gate belongs to the *refresh* triggers (which fire on
/// external events), while a focus only points the model so the pane is ready when it's shown.
```
A focus does not "only point the model" — `HistoryModel.swift:58` is `load(limit: pageSize)`, and `GitProvider.swift:20-32` is `Repository.open` + a 101-commit revwalk + a full ref enumeration (`decorations`) + `GitGraph.unpushed`, an **unbounded** `HEAD --not refs/remotes/origin/*` revwalk. That is not a cheap "point".

It is also undebounced, three lines below the neighbour that documents exactly why it must be. `AppStore.swift:163-165`:
```swift
// Freshen the newly-selected workroom's status (incl. CI) — debounced so arrow-key
// cycling through rows doesn't fork a probe per row (issue #24).
scheduleSelectedStatusRefresh()
```
`scheduleSelectedStatusRefresh` sleeps `selectionDebounce` and cancels its predecessor. `commitHistory.focus` does neither — and `HistoryModel.load`'s `task?.cancel()` **does not stop the work**. `Timeout.swift:63-64`:

```
/// just abandons the result once the closure returns.
```
So arrow-key cycling N sidebar rows dispatches N concurrent full revwalks, each holding a `DispatchQueue.global` thread to completion. Same at launch: selection restore → tab opens → `refreshSelectionHasTabs()` → read, competing with the startup status sweep. This is the exact failure class the same file already records at `Timeout.swift:59-61` ("That's the 'History pane loads forever' bug").

**Caution for the fix:** do not naively add `inspectorIsVisible` to `historySectionShown`. `showInspector` is a bare `@Default`, and per `AppStore.swift:287-289` the inspector content does not observe `@Default` changes — so `HistoryPanel.activationKey` would not flip when the inspector opens, and the un-gated focus is currently the only thing keeping the model's root current while the inspector is closed.
