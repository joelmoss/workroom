**[CRITICAL] (confidence: 8/10) SettingsView.swift:372-376 — turning off "Background sessions" kills currently-attached (visible, in-use) terminals with zero pane-level warning**
```swift
Button("Stop Sessions", role: .destructive) {
  Task {
    guard !Defaults[.backgroundSessions] else { return }
    await PersistentSessionService.shared.endAllSessions()
  }
}
```
`endAllSessions()` maps to `client.killAll()` — it does not distinguish attached vs. detached sessions, and `TerminalSettingsPane` never touches `AppStore`/`TerminalSessions` to reconcile open tabs afterward. A terminal tab the user is actively looking at right now, with `state.sessionID` pointing at a live daemon session, gets its backing process killed. Because ordinary (non-run) tabs wire neither `onChildExited` nor `onCloseRequested` (by design, per the existing doc comment in `GhosttySurfaceView.swift`), the pane just goes inert — no error, no "session ended" message — reproducing exactly the "spinner forever"/dead-terminal bug class called out in project history. The alert copy ("Terminals that are still running in the background will be stopped") also actively undersells this: a foreground, focused terminal is not "in the background."
Fix: before `endAllSessions()`, have this toggle route through `TerminalSessions` (or an app-level coordinator) to detach live-attached surfaces to fresh local shells first, or restrict the kill to sessions with no live attachment.
