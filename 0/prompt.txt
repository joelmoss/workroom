/// Start the project's run command in `target`'s directory, in a dedicated run terminal. No-op
/// without a configured command or for a missing target. One run terminal per target (a second start
/// is a no-op, not a duplicate).
///
/// Issue #67: the run starts in the BACKGROUND by default — `focus` is false, so it doesn't steal the
/// foreground tab; a toast surfaces its status. `focus: true` is only for auto-run on a freshly
/// created workroom where the run would be the sole tab (Arch #5) — there we DO show it.
func startRunCommand(for target: TerminalTarget, focus: Bool = false) {
  guard !target.isMissing, let project = project(forTarget: target) else { return }
  let config = runConfig(forProject: project.path)
  guard config.hasCommand else { return }
  if let existing = runStates[target.id]?.tab {
    // issue #67: a plain start never steals focus — only the auto-run-only-tab case passes focus.
    if focus { terminals.focus(existing, for: target) }
    return
  }
  let pidPath = makeRunPidPath()
  let line = runCommandLine(
    config.command.trimmingCharacters(in: .whitespacesAndNewlines), pidPath: pidPath)
  let tab = terminals.addRunTab(for: target, command: line, cwd: target.path, focus: focus)
  runOutcomes[target.id] = nil  // a fresh run clears the prior outcome (issue #67)
  resetRunToast(for: target.id)  // a new run always gets a fresh toast (clear dismiss + timer)
  if !focus, tab.surface?.didSpawnFail == true {
    runOutcomes[target.id] = .failedToStart
    runStates[target.id] = .stopped(tab: tab.id)
    scheduleRunToastAutoDismiss(for: target.id)
    postRunFailureBannerIfBackgrounded(
      targetID: target.id, tabID: tab.id, title: "Run failed to start",
      body: config.command.trimmingCharacters(in: .whitespacesAndNewlines))
    return
  }
  runStates[target.id] = .running(tab: tab.id, interrupted: false)
  runPidFiles[target.id] = pidPath  // after the tab exists, so cleanup can't wipe it
  lastRunStatus[target.id] = nil
  captureRunSession(for: target.id, pidPath: pidPath)
  pollRunStatus(for: target)  // status file drives state from here (issue #7)
  tab.surface?.onChildExited = { [weak self] code in
    self?.markRunExited(for: target, exitCode: code)
  }
  wireRunClose(tab.id, for: target)
}

## 8. Quit-time graceful teardown — what "waits for" a run command

Chain from `hasLiveRunCommand`/`liveRunView` up to the app-quit and window-close paths:

**Cross-window aggregation** (`Core/WindowRegistry.swift:216-234`):

```swift
/// Any window with a live run command — gates the graceful-stop-on-quit (issue #7 / #70).
var hasAnyLiveRunCommand: Bool { allStores.contains(where: \.hasLiveRunCommand) }

/// Ctrl-C every window's live run commands and let them exit before the process dies...
func gracefullyStopAllWindows(timeout: TimeInterval, completion: @escaping () -&gt; Void) {
  let live = allStores.filter(\.hasLiveRunCommand)
  guard !live.isEmpty else {
    completion()
    return
  }
  let group = DispatchGroup()
  for store in live {
    group.enter()
    store.gracefullyStopAllRunCommands(timeout: timeout) { group.leave() }
  }
  group.notify(queue: .main) { completion() }
}
```

### Consequence chain for an unregistered Investigate tab

Because neither Investigate call site touches `runStates`, an Investigate tab is invisible to every one of the above checks:

`no runStates[target.id] entry for that tab` → `liveRunView` returns nil (guard fails at `runStates[targetID]?.tab`) → `hasLiveRunCommand` is false → `hasAnyLiveRunCommand` is false → **quit**: `stopRunCommandsThenTerminate` sees `!hasAnyLiveRunCommand` and returns `.terminateNow` immediately, no Ctrl-C, no wait — the surface is torn down and the live `claude` process gets a raw SIGHUP; **window close**: `windowShouldClose` sees `!store.hasLiveRunCommand` and returns `true` immediately (no confirm alert, no graceful stop); **⌘W on the tab itself**: `closingRunTab`'s `isRunTab` check is keyed on `runStates[targetID]?.tab == tabID`, which is false (that slot likely still holds the *actual* dev-server run tab, if any, or is empty) — so a live Investigate agent session is freed exactly like an ordinary terminal tab, no different from closing a shell.

Also missing for both Investigate sites, all downstream of the same `runStates`/`onChildExited` gap: no `runOutcomes` entry (no "Failed"/"Exited" outcome tracking), no run toast, no run-state chip in the tab strip/sidebar, no `pollRunStatus`/pidfile capture backstop, and no participation in `WindowRegistry.runOwner` cross-window dedup (arguably correct for Investigate — an agent session isn't a dev server that should be deduped across windows — but the plan should decide this deliberately rather than by accident).

### The core design fork for the plan

`runStates: [TerminalTarget.ID: RunState]` holds **one `RunState` per target** (`Core/AppStore.swift:1371`), and `startRunCommand` explicitly short-circuits when a slot is already occupied (`Core/AppStore.swift:1927-1931`). An Investigate session is a second, independent process in a target that may already have a dev-server `RunState` occupying that one slot. Routing Investigate through `startRunCommand` as-is is not a drop-in — the plan needs to choose one of: (a) a parallel per-tab (not per-target) bookkeeping structure for agent/Investigate run tabs, sharing the teardown/`onChildExited` machinery but not the single-slot `runStates` dict, or (b) widening `RunState` to support multiple concurrent tabs per target. Also decide deliberately whether an Investigate tab should participate in `WindowRegistry.runOwner` cross-window dedup (almost certainly not, unlike a dev server).

### Cheapest immediate win, independent of the above

`Views/TerminalTabStrip.swift:429-444` already binds `state: AgentBannerState` in scope (passed to `TerminalAgentBanner(state: state, ...)`) but its `onInvestigate` hardcodes the literal `"claude"` instead of calling `AgentPrompt.investigateCommandLine(for: state)` as the StatusBar site does at `Views/TerminalStatusBar.swift:326`. Fixing that one line unifies the *command* half of the divergence with zero new plumbing — the *cwd* derivation (three different formulas across the two sites plus the bar's own `cwd` property) and the *bookkeeping bypass* (the harder problem, above) still need the ownership decision.</result>
