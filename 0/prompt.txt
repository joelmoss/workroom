## 5. Existing app-level persistence conventions

Two distinct, deliberately separate mechanisms exist — a new layout-persistence feature should pick the right one:

### A. `Defaults` package — small, global/preference-shaped state
Single source of truth: `/Users/joelmoss/dev/workroom/macapp/WorkroomApp/Core/DefaultsKeys.swift`. Convention, stated in the file's own doc comment (lines 19-26):
- Every persisted value is declared as `extension Defaults.Keys { static let foo = Key&lt;T&gt;("stored.key.string", default: ...) }` — one key owns both the UserDefaults string *and* the default, in exactly one place.
- Read via `@Default(.foo)` in SwiftUI views (synchronous UI binding) or `Defaults[.foo]` everywhere else (stores, non-view code).
- Key **strings** are treated as a stored-data contract — never renamed once shipped (breaks upgrade). Schema reshapes (e.g. `inspectorLayout` → `"inspector.layout.v2"`) get a versioned key name instead, with a `reconcileInspectorState`-style discard-to-default when the persisted shape doesn't match the current one.
- Complex values implement `Defaults.Serializable` (usually via `Codable`), e.g. `RunConfig`, `InspectorPaneState`.
- Enum-backed keys implement `PreferRawRepresentable` so the raw string persists (e.g. `ThemePreference`, `ActivitySection`, `SettingsPane`, `DiffViewMode`).
- This is what backs `showInspector`, `inspectorWidth`, `inspectorLayout`, `sidebarWidth`, `activeInspectorSection`, `mainWindowFrame` (single-slot cold-start fallback), etc. — everything global/machine-wide, not per-window.

### B. `SessionCoordinator` + `SessionSnapshot.swift` — rich, per-window session state
`/Users/joelmoss/dev/workroom/macapp/WorkroomApp/Core/SessionCoordinator.swift` + `/Users/joelmoss/dev/workroom/macapp/WorkroomApp/Core/SessionSnapshot.swift` (schema) + `AppStore+Session.swift` (capture). This is the mechanism for state that is **per-window** and too rich for a single `Defaults` key (issue #46): window frame, selected workroom, open terminal/diff/file/changeset tabs, pane splits, workroom-into-workroom splits, expanded sidebar terminal subtrees. Written to `Application Support/Workroom/&lt;bundle id&gt;/session.json` (hand-written `Codable` mirrors, never the live runtime types — explicit stored-data-contract discipline, with lossy per-element decoding so an unknown future tab kind drops just that one tab rather than the whole document).

Key mechanics relevant to a new feature:
- `SessionCoordinator.shared.markDirty()` — call this on any state mutation; it coalesces (1s debounce, 5s hard ceiling) and calls `writeIfChanged()`, which rebuilds the *whole* document from every live window (`WindowRegistry.captureSessionWindows()`) and writes only if it actually changed.
- **Save-on-background**: `WorkroomApp.swift:275-279` — `AppDelegate.applicationDidFinishLaunching` registers an observer on `NSApplication.willResignActiveNotification` that calls `SessionCoordinator.shared.writeIfChanged()`.
- **Save-on-quit**: `AppDelegate.applicationShouldTerminate` (`WorkroomApp.swift:595-600`) and the SIGTERM handler (`WorkroomApp.swift:499-517`) both call `SessionCoordinator.shared.flushAndFreeze()` (synchronous write, then freezes further writes for the process's life).
- **Restore-on-launch**: `RootWindow.body.task` (`WorkroomApp.swift:150-158`) calls `store.bootstrap(restore: seed.restore)`; `AppStore.attachWindow` (`AppStore.swift:1033-1040`) calls `claimSessionIfNeeded()` before anything reads window geometry, adopting `pendingSessionRestore` (per-window frame, tabs, splits) — this is the concrete "restore-on-launch hook" pattern for *window-scoped* state, as opposed to `loadInspectorState()` in `AppStore.init` for *global* inspector state.
- **What's deliberately excluded from `session.json`**: run-command tabs, PTY/process state, live titles — and, notably, **inspector visibility/width/layout is not captured here at all** (confirmed via `AppStore+Session.swift:captureWindowSession`, which only emits `windowKey`/`frame`/`isKey`/`selectedTargetID`/`targets`/`workroomSplits`/`expandedTargets`). Inspector state lives entirely in `Defaults`, i.e. it is explicitly **global**, not per-window — a new "layout persistence" feature needs to decide up front whether new state is global (→ `Defaults`, like the existing inspector state) or per-window (→ extend `WindowSession` in `SessionSnapshot.swift` + `captureWindowSession`/restore in `AppStore+Session.swift`).

### C. Window frame — the closest existing precedent for "drag-to-resize, persist, restore"
`AppStore.attachWindow` (`AppStore.swift:1033-1125`) is worth studying directly as a template: it reads `Defaults[.mainWindowFrame]` as a cold-start single-slot fallback (`savedMainWindowFrame()`, line 995), but the *authoritative* per-window frame comes from the session file (`pendingSessionRestore?.frame`, line 1089) — clamped onto a still-existing screen via `frameOnAVisibleScreen` (line 1007) so an unplugged external display doesn't strand the window. On resize/move (`NSWindow.didResizeNotification`/`didMoveNotification`, lines 1104-1122) it calls `SessionCoordinator.shared.markDirty()` unconditionally, and *additionally* writes the single-slot `Defaults[.mainWindowFrame]` gated on `persistsSidebarPrefs` (last-active-window-only) purely as the cold-start fallback for a session-less first launch.

## Summary for implementing a new feature

- If the new state is **global** (shared machine-wide setting, like today's inspector open/width/section/collapse layout): add a key to `DefaultsKeys.swift` following the existing pattern (bare key string, `Key&lt;T&gt;(...)`, comment justifying the default), read via `@Default` in views / `Defaults[...]` in stores. No cross-window arbitration exists for the inspector's own keys today (unlike the sidebar prefs) — worth adding `persistsSidebarPrefs`-style gating if targeting multi-window correctness.
- If the new state is **per-window** (e.g., "was the inspector open in *this* window", not a global default): it needs to be added to `WindowSession` in `SessionSnapshot.swift` (a new field, additive — no `schemaVersion` bump per the file's own versioning rule), captured in `AppStore+Session.swift:captureWindowSession()`, and restored via `claimSessionIfNeeded()`/`attachWindow`; changes must call `SessionCoordinator.shared.markDirty()` (or rely on an existing `didSet` chain that already does) to get coalesced-write + save-on-quit/background/SIGTERM coverage for free.</result>
