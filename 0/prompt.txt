2. Key Technical Concepts:
   - SwiftUI + AppKit macOS app, Swift module named `Workroom`, target `WorkroomApp`, deployment target **macOS 15.0**, SDK MacOSX26.5.
   - `NSGlassEffectView` (macOS 26+, Liquid Glass) with `contentView`/`cornerRadius`/`tintColor`/`style`; `NSGlassEffectContainerView`. Fallback: `NSVisualEffectView` `.hudWindow` + `.behindWindow`.
   - `NSVisualEffectView` blending modes: `.withinWindow` (blends against host window backdrop) vs `.behindWindow` (samples desktop/other windows).
   - `NSPanel` with `[.nonactivatingPanel, .borderless]`, `canBecomeKey == false` (load-bearing — the AppDelegate monitor resolves its store from the key window), `isOpaque == false` (load-bearing — `occlusionState` counts only opaque coverage).
   - `NSEvent.addLocalMonitorForEvents(matching: .keyDown)` in `AppDelegate`, running inside `NSApp.sendEvent` before menu key-equivalent dispatch.
   - `NSEvent.modifierFlags` as a **global hardware snapshot** (survives menu tracking / Mission Control) vs a starved local `flagsChanged` monitor.
   - `Timer` added to `RunLoop.main` in **`.common` mode** — `.default` mode does not run during menu tracking or a modal loop.
   - Pure-reducer pattern modelled on `EdgeRevealReducer` (view owns timers, reducer returns `Effect`).
   - FNV-1a hashing because **Swift seeds `String.hashValue` per process**.
   - WCAG contrast: 4.5:1 body text, 3:1 large text / indicators; `ThemeTokens.legible(_:on:towards:target:)` walks a colour **toward the foreground** (right for text, destroys hue for identity marks).
   - **Never round-trip SwiftUI `Color` → `NSColor(_:)`** — yields a lazily-resolved SwiftUI-backed colour whose `usingColorSpace` returns nil outside a view update; re-wrapping crashes in `Color._apply` during layout.
   - `Spacer(minLength: 0)` is a *flexible* HStack child that splits spare width with `Text`.
   - ScreenCaptureKit own-process capture (`SCShareableContent.currentProcess`, `SCContentFilter(desktopIndependentWindow:)`, `SCScreenshotManager.captureImage`) — TCC-free, but **now reverted**.
   - `filter.contentRect` ≠ `NSWindow.frame` (CG y-down vs AppKit y-up, plus insets) — the y-flips do not cancel.
