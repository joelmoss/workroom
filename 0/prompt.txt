### 2. How `environment` is decided

Exact logic (`SentryConfig.swift` lines 66-72):

```swift
static func defaultEnvironment(
  nightly: Bool = ReleaseChannel.isNightlyBuild, debug: Bool = isDebugBuild
) -&gt; String {
  if debug { return "development" }
  return nightly ? "nightly" : "production"
}
```

- Priority order: `debug` wins over everything → `"development"`.
- Else `nightly` (from `ReleaseChannel.isNightlyBuild`) → `"nightly"`.
- Else → `"production"` (this covers BOTH the main Release build subscribed to `stable` and the same build subscribed to `pre` at runtime — there is no separate `"pre"` environment string).
- `debug` is backed by `isDebugBuild` (lines 76-82), a `#if DEBUG` compiler-flag check, stored once as a static constant.
- `SENTRY_ENVIRONMENT` env var overrides the computed value entirely (line 27-28); `SENTRY_DSN` env var overrides the DSN (line 23) but does not affect whether Sentry starts.
- Not based on bundle identifier directly — bundle id differs per build config (`com.developwithstyle.workroom` / `.dev` / `.nightly`) but `SentryConfig` doesn't read it; it goes through `ReleaseChannel.current`/`isNightlyBuild` (Info.plist marker) and `isDebugBuild` (`#if DEBUG`).

**Key finding for your gating design:** The `ReleaseChannel` enum has **exactly three cases: `stable`, `pre`, `nightly`. There is no `dev`/`debug` case at all** — this matches the Go `internal/channel/channel.go` (`Stable`/`Pre`/`Nightly` consts only) and `Scripts/channel-helper.sh` (only classifies into `stable`/`pre`/`nightly`). All three mirror implementations agree: the dev/debug distinction is **not part of the channel model** — it's an entirely separate, orthogonal mechanism.

Detection mechanism: `ReleaseChannel.current` reads the Info.plist key `WorkroomReleaseChannel` (baked at build time from `project.yml`'s `WORKROOM_RELEASE_CHANNEL` build setting):
- Base/`Release` config: `WORKROOM_RELEASE_CHANNEL: ""` → `current == nil` → channel is picked at runtime via `Defaults[.releaseChannel]` (stable/pre).
- `Debug` config: inherits the base `WORKROOM_RELEASE_CHANNEL: ""` (not overridden — see `project.yml` lines 291-302) → marker is empty → `ReleaseChannel.current == nil` and `isNightlyBuild == false`, **exactly the same as the Release build's marker**. Debug builds are indistinguishable from Release by this marker alone.
- `Nightly` config: `WORKROOM_RELEASE_CHANNEL: nightly` (project.yml line 322) → marker is `"nightly"` → `current == .nightly`, `isNightlyBuild == true`. Nightly is release-type (optimized, Developer-ID signed, no `DEBUG` flag) per `project.yml` line 22-24 (`Nightly: release`).

So a Debug ("Workroom Dev") build is currently only distinguishable from a real build via the `#if DEBUG` compiler condition (`SentryConfig.isDebugBuild`), NOT via `ReleaseChannel` — the Info.plist marker gives no dev signal.
