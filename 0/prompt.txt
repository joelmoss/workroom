## Summary

The app already has an extensive, deliberate persistence layer built entirely on the `Defaults` library (no raw `@AppStorage` remains — it was fully migrated, see comments in `DefaultsKeys.swift`). The key finding for this task: **the sidebar's visibility/collapsed state is the one piece of layout state that is explicitly NOT persisted** (session-only, resets to visible every launch), while nearly everything else (widths, inspector open/closed, selection, window frame) is persisted, either via a global `Defaults` key or via the per-window `session.json`.

## 7. `NavigationSplitView`/`columnVisibility` binding type — direct answer

`columnVisibility` in the one real `NavigationSplitView` (`RootView.swift:142`) is **`.constant(.detailOnly)`** — a hardcoded constant, not backed by `@State`, `@AppStorage`, or `@Default`. It carries no runtime meaning; the native column is empty and unused. Real sidebar/inspector visibility is driven by separate booleans (`store.sidebarVisible` — plain `@Published`, unpersisted; `showInspector` — `@Default`-backed, persisted).
