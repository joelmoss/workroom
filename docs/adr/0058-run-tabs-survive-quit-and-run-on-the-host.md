# Run tabs survive quit like any terminal, quit remembers whether to stop dev servers, and a remote workroom's run runs on its host

Decided 2026-10-23 (owner, grilling for #522). Status: accepted, not yet built. Supersedes the "run tabs are never kept" rule (`TerminalPersistentSessionPolicy`, `TabSession.init?`, `PRODUCT.md`, the user docs and the quit dialog) and answers open question 4 of [`docs/designs/remote-workrooms.md`](../designs/remote-workrooms.md).

Run tabs were never kept only because run commands (#7) predate persistent sessions: the supervisor was built as libghostty's own pty child, and when sessions arrived the run tab was left out. `TabSession.init?` gives the one written reason, that restoring a run tab would start a dev server again with no run state behind it, orphaned on its port. A kept run reattaches to the server that is still running, so that reason no longer applies, provided the app rebuilds the run's state on relaunch. So a run tab is a terminal like any other and survives quit, an update relaunch and a SIGTERM quit, on this Mac and on every remote kind alike (exe.dev, boxd, containers; SSH hosts with #378). The supervisor runs inside a daemon session, and on a remote workroom inside a session on the host, so its parked "exited N" state survives a closed app. A stopped run tab survives too. On relaunch a still-running run reattaches without a "Running" toast. A run that finished or failed while the app was closed comes back parked, with its outcome, toast and "Run failed" banner, but never auto-diagnoses. A run whose session is gone (a reboot, a daemon death) comes back as a stopped Run tab that says it ended while Workroom was closed, and ⌘R starts it again. Nothing restarts a run by itself. Quit has one setting, "When quitting with dev servers running" (Settings ▸ General, under "Confirm before quitting"), with the values Ask (the default), Keep running and Stop. While it is Ask, the first quit with a live run asks, whether or not quit confirmation is on, saves the answer and names the setting. A SIGTERM quit follows the setting and keeps runs while it is still Ask. An update relaunch always keeps runs. Deleting a workroom or project and closing a run tab still stop the run first. Investigate tabs still stop at quit (owner: no). Ports are left alone: boxd and exe.dev publish their own, and a container run is reachable through the ports its `devcontainer.json` declares or the user adds. Nothing detects a run's port. The daemon gets a request to signal a session's supervisor, since a remote run has no local pid to `kill()`.
