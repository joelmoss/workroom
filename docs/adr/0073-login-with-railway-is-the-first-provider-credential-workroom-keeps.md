# Workroom signs in to Railway with Login with Railway, and keeps the refresh token in the Keychain: the first provider credential Workroom stores itself

Proposed 2026-11-13, from the Railway sandboxes design interview. It is accepted once the live spike shows a Native app refreshing its token without a client secret and Railway accepting the localhost redirect.

boxd and exe.dev are driven through their own CLI and ssh, and Workroom holds no credential for either. Railway's CLI has no region or size flag for a sandbox, so every host would land in `us-west2` at the plan's default size, and it rewrites the "active sandbox" in the user's `~/.railway/config.json` on every create, ssh and exec. So the Railway driver calls Railway's GraphQL API itself and reaches a host with the system `ssh` through the relay, with a key Workroom makes for each Mac and registers on the account. Codaset registers a Native (Public) OAuth app with Railway: no client secret, PKCE required. The setup sheet opens Railway's consent page in the browser and takes the callback on a fixed localhost port, asking for `workspace:member`, `project:member` and `offline_access`. The refresh token goes in the Keychain, in an access group Release and Nightly share; a Dev build keeps its own. Access tokens last an hour and are refreshed by one owner at a time, which always stores the newest refresh token, since a rotated one fails and forces a new sign-in. Signing out is allowed while Railway workrooms exist, with a warning that their sandboxes keep running and billing; they show signed out, with Sign in, until the user signs in again.

Rejected: driving the user's `railway` CLI, for the region, size and config side effects above. Rejected: a pasted workspace or account token. It is one manual copy from Railway's dashboard, and an account token reaches every workspace. Rejected: reading the CLI's session from `~/.railway/config.json`, a private format. Rejected: a project token, which can't register an ssh key.

Source: [`docs/designs/railway-sandboxes-research.md`](../designs/railway-sandboxes-research.md) (section 5), Railway's OAuth docs: <https://docs.railway.com/integrations/oauth/creating-an-app> (app types) and <https://docs.railway.com/integrations/oauth/login-and-tokens> (refresh and rotation).
