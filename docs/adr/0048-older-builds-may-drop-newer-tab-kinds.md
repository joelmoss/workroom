# An older build may drop a newer build's tab kinds from a shared host layout, and a newer schema version is read-only

The host layout blob reuses the `session.json` codec unchanged. A build that cannot decode a tab kind drops it, and its next write through removes that tab from the host layout for every Mac, the same trade that rolling `session.json` back to an older build already accepts. Terminal sessions survive through the append rule (see ADR 0046), so only a tab of a kind the older build does not know (a newer non-terminal kind) can be lost. A breaking `schemaVersion` bump is different. An older build treats a newer blob as read-only, restoring nothing from it and writing nothing over it, so it cannot destroy a newer build's layout. Additive changes, such as a new tab kind or an optional field, never bump the version, because a bump would discard every saved session. The rejected alternative was that an older build never writes over a newer build's layout. It would keep every tab but silently stop one Mac's changes from syncing for as long as that Mac stays on the older build.

Source: [`docs/designs/oq8-cross-machine-reattach.md`](../designs/oq8-cross-machine-reattach.md) (C3), [`macapp/WorkroomApp/Core/SessionSnapshot.swift`](../../macapp/WorkroomApp/Core/SessionSnapshot.swift) ("Versioning rule"), [`macapp/WorkroomApp/Core/HostLayout.swift`](../../macapp/WorkroomApp/Core/HostLayout.swift) (`schemaVersion`), [`macapp/WorkroomApp/Core/HostLayoutSync.swift`](../../macapp/WorkroomApp/Core/HostLayoutSync.swift) (a `.newer` layout is never written over).
