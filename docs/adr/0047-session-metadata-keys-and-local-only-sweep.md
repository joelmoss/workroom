# Session metadata rides the forwarded environment and is bounded, layouts are keyed by the workroom's own id, and the orphan sweep stays on local sockets

A session's workroom id and title come from `WORKROOM_SESSION_WORKROOM` and `WORKROOM_SESSION_TITLE` in the environment the attach client already forwards, plus a creation time that `wr-agent` adds. An id over 2048 bytes drops all the session's metadata, and a title is cut at 256 bytes on a character boundary, so one long title cannot fail the list reply for a whole host. A 64-byte id cap was rejected because local ids embed the project path. Sessions with no metadata are never swept, never ended by a workroom match and never appended. A remote workroom's layout key and its sessions' tag are the workroom's own id, never `target.id`, which embeds this Mac's project path; local sessions are tagged with `target.id`, and local layouts stay in `session.json`. The orphan sweep and the delete-by-workroom match run only against this Mac's local sockets, because a sweep of a shared host would end the other Mac's sessions. So the app does not sweep a remote host's sessions at launch, and no test pins the local-only sweep.
