# The host executes VCS writes and one Swift classifier decides what they mean, and an unanswered write is never retried

A remote workroom's commits, fetches, pushes and pulls run as `git` on the owning host through wr-agent's generic exec service, but argv building, output parsing and failure classification stay in the one Swift `CLIVCSWriter` (see ADR 0003), so a failure means the same on both paths. A second classifier inside wr-agent was rejected, because the exec service is deliberately not a reimplementation of commit, push and pull. One classifier was still not enough on its own: it had reached opposite verdicts when the two paths fed it different input, such as a stale identity or a completed push reported as never started, so both paths now give it the same environment, exit codes and error partition. No write is replayed after a connection loss, because a failed wait does not show whether the host applied it. A write that was sent and never answered is its own failure, `outcomeUnknown`, and its retry action is a fetch for a push or pull, since offering a push that may have landed again is the one thing it must not do. Nothing from the Mac's environment goes to a remote host: wr-agent builds the environment from the host's own, so Mac credentials do not cross.
