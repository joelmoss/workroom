# Local container workrooms ride the remote path, and may take git credentials from the Mac's gh through a loopback relay

A workroom can be created in a Docker or Apple `container` runtime on the Mac. It uses the same `ContainerHostDriver`, wr-agent and panes as a remote host, reusing the tested path, so it is a remote workroom whose host is a container on this Mac and, unlike one on a provider's host, it stops when the Mac sleeps. Its git credentials come from the broker when the user is signed in to Codaset (see ADR 0024). When the user is not, or the repository's owner has not installed the App, they come from the Mac's `gh` through a relay: a per-launch secret and git's request travel over the app's connection to a listener on the Mac's loopback, which answers for `https://github.com` only. The cost is accepted: anything in the workroom can read the secret and ask, so it has the user's `gh` access, as a workroom on the Mac does. A token it was given works until the user revokes it. A remote provider's host never uses the relay and always enrols. A Codaset sign-in is not required: a `gh` sign-in is enough.
