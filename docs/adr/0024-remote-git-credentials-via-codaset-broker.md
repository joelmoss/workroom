# Remote workrooms on a provider get git credentials only from a broker that Workroom runs, as one-hour installation tokens

Decided 2026-09-27. Remote workrooms on a provider (boxd, exe.dev) fetch and push with credentials minted by a broker that Workroom operates (Codaset), never with a deploy key, a per-VM device flow, a provider's own GitHub connection, or the Mac's `gh` token. A workroom in a container runtime on this Mac may instead take a relay that answers from the Mac's `gh` (#309); that path is not covered here. The user signs in once, a one-time code enrols the instance, and the instance then mints its own tokens with the Mac closed. Creating a workroom on a remote provider therefore requires being signed in to Codaset. Git receives a one-hour GitHub App installation token narrowed to one repository, minted after the broker checks the user may push, not the user's own scoped token: GitHub documents a cap of ten tokens per user, application and scope for OAuth apps and says nothing for GitHub App user tokens, so one token per workroom would break for anyone with more than ten workrooms if the cap applies; nobody has measured it, and installation tokens have no per-user cap. The costs are accepted: pushes appear from the App's bot, and an organization owner or repo admin must install the App once per organization. The per-mint check and the App's registration live in Codaset, not in this repository.
