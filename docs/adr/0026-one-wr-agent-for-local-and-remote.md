# One wr-agent serves local and remote workrooms, written in Rust in the `vcs/` workspace

Local and remote workrooms run the same wr-agent code. Locally it listens on a Unix socket and remotely it serves whatever stream a host driver opens, so every local session is the remote path's test harness. It is Rust, in the `vcs/` Cargo workspace, and it replaced the Swift pty daemon instead of proxying to it (see ADR 0008 for what survives of that daemon). The reason is parity: separate local and remote paths diverge by construction, and one wr-agent for both is the only way parity holds without continuous manual reconciliation. The rejected alternatives were a remote-first slice, which leaves the Swift daemon local and the Rust wr-agent remote for weeks, a two-speed wr-agent whose local reads and far-side git shell-outs could disagree silently, and Swift on Linux or Go, which would be a third rewrite. The accepted cost is a multi-thousand-line port of the pty daemon and its replay buffer with no measurable local dividend.
