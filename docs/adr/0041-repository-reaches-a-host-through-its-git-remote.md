# The repository reaches a host only through its git remote, and only from GitHub.com

A remote workroom's repository is cloned on the host from the project's GitHub origin, by the origin's own URL when that is an `https://github.com/` or `git@github.com:` URL naming the repository and over https otherwise (`RemoteWorkrooms.cloneURL`), and the workroom's own branch is then checked out. The local working copy is never synced, and unpushed local work is not carried over, so work in progress on the Mac does not appear on the host until it is pushed. Every remote workroom is a fresh host (see ADR 0017), so there is no shared `.git` to make a worktree from, and syncing the working copy was rejected. Remote workrooms require a github.com origin, because a workroom's pull request status runs through the Mac's `gh` against github.com (see ADR 0033) and the providers' GitHub integrations answer for GitHub only (see ADR 0049), and a project whose origin is elsewhere is refused. Non-GitHub remotes stay an open question in the design (OQ6): a plain git-over-ssh remote has no answer for credentials.
