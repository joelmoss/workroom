# The wr-agent protocol is versioned, the newest wr-agent wins, and no numbered build downgrades one

The multiplex envelope is versioned from the first commit. A host keeps the newest wr-agent any build pushed, so a Release app can face a Nightly's wr-agent (see ADR 0036), and `MIN_SUPPORTED_VERSION` must never rise above the protocol the latest stable app speaks; `agent-protocol_test.sh` pins that. Order comes from a build number: each wr-agent embeds its commit time in seconds and reports it as `build-number`. The app pushes only when the host's number is lower (an equal number with a different hash still pushes). Hand-off (see ADR 0009) refuses a program with a lower number. Without an order, two Macs on different builds would swap the host's wr-agent, and shipped apps still run the old hash rule. Ordering by protocol version alone was rejected, because bug-fix builds would never reach a host. Accepted: a build with no number (an unnumbered or legacy app) is never kept out, so it can overwrite the binary while nothing listens (a running numbered wr-agent still refuses its hand-off), and the next newer app re-upgrades it, keeping shells; commit time does not order builds across branches, so a dev build can pin a host.
