# A local wr-agent exits when idle, and a remote wr-agent is supervised and never idles out

The local wr-agent has no supervisor. `wr-agent attach` spawns it detached when a connect finds nothing listening, a lock file allows one instance, and it exits when its last pty and last client are gone, because diffs, history and watches are things a connected client asks for, so a wr-agent with no clients and no ptys holds nothing to lose. An earlier draft of the design claimed local needed supervision and was corrected. A remote wr-agent must keep its sessions with no client attached, so each host runs it under a supervisor (a systemd unit on boxd and exe.dev, the image's entrypoint loop in a container host) with `--idle-timeout never` and `--screens`, restarted whenever it exits, and the app reaches it through `wr-agent relay --socket`, which only copies bytes. `serve --stdio` ties its sessions to one connection and kills them when the stream ends, so it stays a transport test entry point and never owns a host's sessions. The cost is a long-lived daemon on every host.
