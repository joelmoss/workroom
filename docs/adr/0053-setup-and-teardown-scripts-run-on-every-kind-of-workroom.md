# Setup and teardown scripts run on every kind of workroom

Decided 2026-10-17 (owner). Supersedes the "No teardown script runs on the host" sentence of [ADR 0040](0040-deleting-a-remote-workroom-is-app-only.md); the rest of 0040 stands.

`scripts/workroom_setup` and `scripts/workroom_teardown` behave the same on every kind of workroom, wherever they can. A remote workroom (boxd, exe.dev, a Docker or Apple container) runs its setup script on its host after "Copy local files", under the local create's "Run setup script" row, and its teardown script on its host before the host is destroyed. The checkout's copy runs, else the root's, copied to the host with its mode. Both run through `wr-agent run-script`, over the app's own connection (`RemoteHosts.connect`), which replaces an older agent and puts a container's git credential relay up. `run-script` reads the host user's login-shell environment the way the app reads the Mac user's, streams the script's output, and kills the whole tree on a 600 s wall clock or a signal.

What can't match: a host has no root project, so `WORKROOM_ROOT_PATH` and `WORKROOM_PARENT_DIR` are unset there, and a new `WORKROOM_HOST` (`local`, `boxd`, `exedev`, `docker`, `apple`) says where a script runs; a host script gets the host's environment, never the Mac's (#229); and the engines differ (the Go CLI locally, the app remotely), pinned to one contract by `testdata/script-env`. Scripts run by default, with no opt-in, so a script that requires the root path fails on a host until it is guarded.

A teardown that fails, can't start, runs out of time, or whose host can't be reached stops the delete with nothing removed, locally and remotely, and the app offers Delete Anyway (`--skip-teardown`, `RemoteWorkrooms.Teardown.skip`), only for those failures. On a project delete it skips every remaining workroom's teardown, so its button says so: Delete Without Teardowns. A teardown runs whenever a workroom itself is destroyed: every project-delete scope destroys remote machines, so each runs its remote teardowns; config-only leaves local worktrees on disk and runs no local teardown. A host left `creating` or `failed` is destroyed without its script. A script that can't start is the script's failure (exit 5), not an internal error.

Rejected: an opt-in per project (nothing would run until found and flipped); setting `WORKROOM_ROOT_PATH` to the clone (scripts copying from the root would copy the clone into itself); destroying the host when its teardown fails (outside resources would leak silently); a shell wrapper instead of `run-script` (it would re-implement tree kill and the login probe, worse); the agent's `exec` request (no live output, and a git-shaped environment).
