# wr-agent became workroomd, the Workroom daemon, and only a handful of things keep the old name

Decided 2026-10-22 (owner, #525; eng review D1 to D6). "Agent" meant both the Rust daemon and Claude or Codex, in the app's own messages, so the daemon was renamed in full: the crate, the binary, the Swift and Rust names, the scripts and CI, the host layout and the words. Coding-agent names say `CodingAgent`, and the retired Swift `workroom-session` is the legacy session helper, never a daemon. "Server" was rejected because an SSH host (ADR 0056) is literally a server, and "service" because the daemon's parts are already called services.

Stable users updating from v2.1.0 keep every terminal, but not by hand-off: v2.1.0's daemon speaks protocol 1 and predates hand-off (protocol 6), so it refuses one and keeps running. The app finds it under its old socket name, `agent.sock`, by whichever socket answers, in both socket directories (the longer name moves some paths past `sun_path`), and uses it until it exits; the next daemon is `workroomd` on `workroomd.sock`. A daemon new enough to hand off keeps its old argv, lock and log across the exec, so nothing renames a running daemon's socket either (D4). Hosts get only the new names: only Nightly and Dev builds made hosts before the rename (D2: it lands before the first stable with remote workrooms), and their supervisors start the old name, which the app cannot change without root or a new image, so such a host is refused with a message to recreate the workroom (D3).

What keeps the old name, and why:

- The `WRA1` protocol magic: invisible, and changing it would cut the app off from every older daemon.
- The command line an older daemon or installer runs on the new binary: `protocol` and its `build-number <n>` line (how builds are ordered, ADR 0037), `handoff-check <table>`, and `serve` with `--socket`, `--handoff`, `--idle-timeout` and `--screens`, plus the hand-off table format. Pinned by `vcs/crates/workroomd/tests/cli_contract.rs`.
- Until #526: the app's `agent.sock` lookup, the old-layout host detection (`wr-agent` in `agent/` or `/run/workroom`), and the pinned v2.1.0 daemon (`macapp/WorkroomAppTests/Fixtures/wr-agent-v2.1.0`) that proves the update. `macapp/Scripts/daemon-name_test.sh` fails on the old name anywhere else.
- History: the frozen design docs, `docs/recently-done.md`, quoted issue titles, and ADR file names (they are links).

The build marker `WR-AGENT-BUILD:` was not kept: only the same process and the same build's scan of its bundled Linux daemons read it, so it was renamed with that scan. Rejected: aliases on every host plus legacy-invocation handling in the daemon (code that runs only after a host restarts, resting on unchecked Linux socket behaviour); renaming the socket inside the daemon after a hand-off (it touches the one step where a failure ends every shell, and v2.1.0 cannot hand off anyway).
