# `AppEnvironment` has two independent axes: services and isolation

Status: accepted, not yet built. The test-fixture branches in production code are to be replaced by an `AppEnvironment` with `services` (live or fixture) and `isolation` (none or testProcess). Isolation is derived from the three signals the test-process check reads today, and it is selected before `UserDefaults.app` and the shell and ghostty probes are evaluated. A UI-test launch that runs the real bootstrap without fixture data maps to live services with test-process isolation: folding it into either existing mode would overwrite the developer's own preferences or stop testing the real bootstrap. The fixture file is to be wrapped in `#if DEBUG`, so a Release build compiles none of it; today it is compiled into Release and gated at runtime by `enabled`.

Source: the maintainer's architecture cleanup plan (a private planning document, not in this repository), engineering review decision D10 (2026-10-10); the signals are in `macapp/WorkroomApp/Core/UITestFixture.swift` and `DefaultsSuite.swift`.
