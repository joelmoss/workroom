# `AppEnvironment` has two independent axes: services and isolation

Status: accepted, not yet built. The test-fixture branches in production code are to be replaced by an `AppEnvironment` with `services` (live or fixture) and `isolation` (none or testProcess). Isolation is derived from the three signals the test-process check reads today, and it is selected before `UserDefaults.app` and the shell and ghostty probes are evaluated. A UI-test launch that runs the real bootstrap without fixture data maps to live services with test-process isolation: folding it into either existing mode would overwrite the developer's own preferences or stop testing the real bootstrap. The fixture file is wrapped in `#if DEBUG`, so a Release build compiles none of it.

Source: [Workroom architecture cleanup plan](https://claude.ai/code/artifact/7c4e90b9-19c7-4283-b5c6-846f6919e17e), engineering review decision D10 (2026-10-10); the signals are in `macapp/WorkroomApp/Core/UITestFixture.swift` and `DefaultsSuite.swift`.
