# Orphaned provider hosts are swept only when recorded as pending, and the provider account is checked before every create, destroy and rollback

A provider driver writes a pending record before the call that creates a host, and clears it once config records the host. At launch only a pending entry that two launches in a row found unrecorded, and that is over an hour old for a provider host, is destroyed, at most three per sweep. Nothing lists every `workroom-*` host on a provider and deletes the unknown ones, because names carry no build and no one config holds every build's hosts (a Dev build keeps its own), so a listing would take another build's create still in flight. A container host is swept by its build's Docker labels under the same two-launch and three-per-sweep rule, with a 20 minute grace. The boxd and exe.dev drivers also check that the signed-in account (and boxd's active org) match the host's record before every create, destroy and rollback, and treat "not found" as gone only if that check passes. In another account a host reads as not found, and `destroy` would leave a billed host running. The org alone is not enough, since a personal account's org is always nil. The check is not a pin: a switch between the check and the call still lands that call in the other account, and closing that needs a credential fenced to one org.
