# Which helper owns a terminal session is resolved per session, never per app, and there is no Swift helper fallback

Every new session goes to `workroomd`. An existing session resolves to whichever helper owns it, once, and the answer is cached, because a pane asks twice (for the binary and for the socket) and the two must agree. An unanswered ownership probe resolves to neither and the pane opens a plain shell, and if the daemon fails its own probe `preferred()` returns nil instead of falling back to the retired Swift helper. Both helpers create a session on attach for an id they do not hold, so every guess forks a second pty and orphans the user's shell: there is no safe direction to guess. An app-wide switch would strand the terminals running when it flipped.
