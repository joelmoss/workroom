# Restoring a layout never prunes a pane, and a remote pane whose session is gone shows "ended" instead of a new shell

On restore every terminal tab in the host layout is kept and attaches with `existing_only`, and the answer decides the pane. A live session reattaches, a session that ended with its host shows its frozen last screen, and a missing one stays as an ended pane until the user closes it. Sessions tagged with the workroom that the layout does not name are appended as solo tabs. That append makes last writer wins safe, since a stale write cannot lose a live session. Pruning against the live list would have dropped every pane a host reboot left as a recorded screen. For a remote pane with no session and no recorded screen, the attach client says the terminal has ended and to close it, then holds with input discarded, exiting 0 because 255 would read as a dropped link and be attached again. A fallback shell would be the attach client's own child, unlisted, dead with the ssh link and invisible to the other Mac; local panes keep it, and a remote user opens a new tab instead. Known limit: the append covers live sessions only.
