# Terminal events reach the app through one synchronous typed sink, not an AsyncStream

`TerminalSessions` reports to `AppStore` through one `onEvent` callback carrying a `TerminalSessions.Event` enum, delivered on the main actor as a plain call at the moment each thing happens, in the same order the old separate closures fired, with no `AsyncStream`. Navigation replay suppresses history recording only within a synchronous scope, and `select` must raise the surface-focused event before the focus change so history records against the right workroom; an asynchronous stream would deliver replay events after the suppression scope closes. `AppStore` switches over every case, so a new case cannot go unhandled. The `TerminalSessionsTests`, `DetachedPaneTests` and `AppStoreCloseTabsTests` assertions are the regression contract.

The layer below follows the same rule. A `GhosttySurfaceView` reports to `TerminalSessions` through one `onEvent` callback carrying a `SurfaceEvent`, set by `TerminalSessions.wire` when the tab is made and again when another window adopts it, and raised as a plain synchronous call where each separate closure used to fire. Nothing else assigns it, so `AppStore` hears a tab's process exit and a run tab's close request as `TerminalSessions.Event` cases and matches them to its run by tab id, rather than wiring closures that a window move had to overwrite. Only the queries that must answer at once (`onOpenURL`, `resolveCmdHoverFile`, `moveToWorkroomChoices`) stay closures.
