# A pane whose session is gone resumes the program that reported itself over OSC 7577, with no trust rules

Decided 2026-11-26 (owner, grilling on [`docs/designs/rex-program-resume-research.md`](../designs/rex-program-resume-research.md) and [`docs/designs/osc-7577-herdr-research.md`](../designs/osc-7577-herdr-research.md)). Status: accepted, not built. Supersedes in part [ADR 0046](0046-restore-never-prunes-an-ended-pane-stays.md): a pane whose gone session left a resume record no longer comes back as a new shell (this Mac) or "ended" (a host).

The daemon keeps a session's process alive through a quit, an update relaunch and a dropped link. What it cannot survive is a Mac reboot, a daemon crash or a host restart, and there every coding agent's conversation was lost. Workroom adopts the Program Resume Protocol (OSC 7577, Rex's draft, v0.5 of 2026-11-25), which Rex and Herdr both implement: a program that reports how to start itself again comes back in its pane, and Claude Code, which does not report yet, reports through a hook Workroom installs. Codex resumes once it reports itself. Resume happens only where a session is gone; a live session reattaches as before. A shell that reported nothing comes back as a new shell, and a run command keeps ADR 0058 (a stopped tab, ⌘R).

An authenticated report is run again as reported, with no per-program rules, flag lists or directory limits: Herdr's model, not Rex's. A report counts only with its session's token, a valid `mac`, a `time` within 60 s and not older than its owner's last, from a live process (pid and start time) under the session's first process, run by the same user and never as root. A process that can forge that already runs as the user and could as easily edit their startup files. The token is what keeps a remote machine's output or a `cat`'d file from making records, and that is the risk worth guarding. Known limit: the spec asks a program that runs children with fewer rights, such as a coding agent's sandboxed tool calls, to strip the token from them, and Claude Code and Codex do not yet, so such a tool call that can write to the pty could register a command that a later resume runs with the user's full rights. Rules would not close that either, since the planted command can be `claude --resume` with flags of its choosing. The off switch is one setting, "Resume programs after a restart" (Settings ▸ Terminal, on by default); turned off, the daemon accepts no reports and the hooks are removed.

The daemon reads reports from the raw pty bytes itself, since libghostty has no OSC 7577 parser (Ghostty `main` at `4ebafeb`, 2026-11-26, has no issue, PR or code for it). It ports Herdr's `protocol.rs` and its tests, under Apache-2.0 with the licence, changed-file notices and a `make notices` entry. Every interactive session gets a new `OSC7577_TOKEN` when it starts; run sessions, `workroom exec` and the terminal API's own processes get none, and the token is never saved or passed through `workroom attach` or a port forward. The one exception is a hand-off, where the shell keeps its token across the daemon's replacement: the hand-off table carries each session's token and records to the next program, written `0600` and removed once it is read (#822). Where Herdr departs from the spec, Workroom follows the spec: a rejected report removes all of its owner's records; a record clears when its owner exits (after a 2 s grace, so a shutdown's dying agent keeps it), on `clear=1` and when its tab closes, and never when its session dies; the folder is the report's `cwd`, else the owner's, else the pane's saved one (its OSC 7 folder), and a reported `cwd` that no longer exists means no resume. Herdr's stream-offset guard against a replayed report is kept.

Claude Code reports through a `SessionStart` hook in each Claude profile's `settings.json`, on the Mac and each host. It is installed only while the setting is on, beside the user's own hooks, and a marker in its command makes it Workroom's to update or remove, as the Workroom skill's does. It runs a `workroom` helper that builds `claude --resume <id>` from the hook's `session_id` and the agent's own arguments. The helper keeps a fixed list of flags that shape a session (`--model`, `--permission-mode`, `--dangerously-skip-permissions`, `--add-dir` and the like), drops prompts, `-p`, `--continue`, `--resume`, `--fork-session` and anything after `--`, and reports nothing when it meets a flag it does not know. A profile other than the default goes in as `env CLAUDE_CONFIG_DIR=…`, because the protocol carries no environment. It writes the report as the agent's pid to the agent's own tty device (`/dev/ttysNNN`, read from the agent's process), never to stdout, which Claude hands to the model, and not to `/dev/tty`: an agent runs its hooks with no controlling terminal. Claude may ask the user to trust the folder. [The spike](../designs/osc-7577-hook-spike.md) proved this end to end for Claude Code 2.1.332: the token reaches the hook, the hook's parent is `claude` with its full arguments, and the report arrives on the pane's output. When an agent reports natively (anthropics/claude-code#112408), the hook's report repeats the same command.

Codex gets no hook (owner, after the spike). An interactive Codex runs its sessions, and so its hooks, in a shared background server (`codex app-server --managed-daemon`, a child of launchd with no tty) whose environment and process tree belong to whichever terminal started it, so a hook cannot tell which pane it serves: in the spike its write to a tty failed. The interactive client runs in the pane and knows its session, so that is where a report belongs. A Codex pane resumes once Codex sends OSC 7577 itself, and until then comes back as a new shell, as today.

The daemon keeps each session's record beside its program status, and the app saves it in that tab's saved-layout entry: `session.json` on this Mac, the host layout for a remote workroom, both written `0600` because a report's arguments can hold secrets. The app sends the record with its request to recreate the gone session under the same id, and the daemon starts the login shell, which runs the program in its folder, so quitting it or a failed start leaves a shell prompt. The daemon makes one session per id, so two Macs that reconnect after a host restart resume it once. The host's daemon starts it, which answers ADR 0046's objection to a remote fallback shell (an unlisted child of the attach client); a fresh host has no host layout and so no record, and its pane still says it has ended. Hidden tabs resume as they reconnect, so their program-status marks come back. The pane shows nothing while it merely holds a record. A resume toasts "Resumed Claude Code" or "Resumed `<program>`", and a program that exits with an error within 5 s turns that into "Couldn't resume `<program>`". `workroom sessions --json` adds a `resume` object (`program`, `cwd`, `reported_at`, never the arguments), which ADR 0079 allows, and the daemon logs every ignored or rejected report with its reason, naming the program and never its arguments.

## Considered options

- **Rex's trust rules** (`resume.trust.*` in user config: per-program command shapes, flag lists, directory limits). Rejected: they guard against a same-user process that already has easier ways to run code at login, at the price of a config language and a "why didn't it resume" debugger.
- **Only Claude and Codex, with Workroom building the command over a private daemon request.** The first decision of the grilling, dropped once Herdr shipped OSC 7577: the protocol brings every program that reports (Pi already does), and the same hook then works in Rex and Herdr.
- **A Codex hook that reports to Workroom's daemon instead of the pane**, matched to the one session in the hook's folder with `codex` in the foreground, and nothing when there are none or several. Rejected (owner): it guesses at a pane, it works only when Codex's server was started from a Workroom pane, and it asks the user to trust a hook for that.
- **Running Codex without its shared server** (`--no-daemon`). Rejected: it changes how Codex runs for everything the user does, to serve Workroom.
- **Guessing the conversation from transcript files.** Ambiguous when two agents share a workroom, and a running `claude` keeps no transcript open to tie it to its process (checked with `lsof`, 2026-11-26).
