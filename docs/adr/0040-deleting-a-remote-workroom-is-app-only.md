# Deleting a live remote workroom is app-only, and the Go CLI refuses

The app tears a remote workroom down itself: it cancels the broker grant, releases the workroom's route to the broker and destroys the host, then has the CLI drop the entry. The CLI deletes only a workroom whose host is already `destroyed`, and `delete-project` refuses, in every mode, a project that still has remote workrooms. Both refuse with `RemoteWorkroomUnsupported`. The host driver is Swift and the broker key is the Mac's (see ADR 0025), so a standalone CLI cannot take a host down, and dropping the entry first would orphan a billed host and a live grant. A CLI that deletes remote workrooms itself was rejected. No teardown script runs on the host: create runs no setup script there either, and the host goes anyway. If part of the teardown fails, the entry stays as `failed` with whatever is still live, so deleting again finishes the job.
