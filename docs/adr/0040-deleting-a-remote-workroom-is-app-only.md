# Deleting a live remote workroom is app-only, and the Go CLI refuses

The app tears a remote workroom down itself: it destroys the host, then has the CLI drop the entry. The CLI deletes only a workroom whose host is already `destroyed`, and `delete-project` refuses, in every mode, a project that still has remote workrooms. Both refuse with `RemoteWorkroomUnsupported`. The host driver is Swift, so a standalone CLI cannot take a host down, and dropping the entry first would orphan a billed host. A CLI that deletes remote workrooms itself was rejected. No teardown script runs on the host: create runs no setup script there either, and the host goes anyway (superseded by [ADR 0053](0053-setup-and-teardown-scripts-run-on-every-kind-of-workroom.md): both scripts now run on the host). If part of the teardown fails, the entry stays as `failed` with whatever is still live, so deleting again finishes the job. On an SSH host the app removes only the workroom's folder and never destroys the host (narrowed by [ADR 0056](0056-ssh-hosts-are-the-users.md)).
