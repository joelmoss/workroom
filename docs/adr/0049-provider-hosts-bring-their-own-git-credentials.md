# A remote provider's host fetches and pushes with the provider's own GitHub credentials, and Workroom runs no broker

Decided 2026-10-12, superseding ADR 0024 and ADR 0025. Workroom gives a remote provider's host no git credential. Each host uses its provider's defaults: a boxd machine uses the user's boxd `git` integration (`boxd manage integrations connect git`), and an exe.dev VM uses an exe.dev GitHub integration the user makes per repository (`integrations add github --repository <owner/repo> --act-as-user --attach auto:all`). Configurable options can come later if a need shows. The Codaset broker, the Codaset sign-in and the Mac's device key are removed, so a remote workroom needs no Codaset account. The owner chose this because Codaset had no other use for an account, because pushes must be in the user's name (a GitHub App installation token always pushes as the App's bot), and because broad repository scope inside the VM is acceptable.

A spike on 2026-10-12 proved both providers clone and push in the user's name with their defaults, the GitHub activity API recording the user as the pusher. On boxd, system git config already has `credential.https://github.com.helper=boxd` and an `insteadOf` from `git@github.com:` to https. On exe.dev, the integration answers only at `https://github.int.exe.xyz`. So the exe.dev driver sets a system `insteadOf` from every GitHub remote form (https, scp and `ssh://`) to that host, and `GH_HOST` for login shells (`Resources/host-setup/exedev-github.sh`). The rewrite covers every GitHub repository, not only the project's: that host also serves public repositories with no integration, so a workroom's public git dependencies, submodules and `gh` reads still work (probed 2026-10-12: `ls-remote`, a clone and `gh repo view` of three public repositories). A workroom clones the project's origin URL as it is only when that URL starts with `https://github.com/` or `git@github.com:` and names the project's repository; any other origin (`ssh://`, another repository `gh` resolved) is cloned over https (`RemoteWorkrooms.cloneURL`).

There is no preflight. When the clone fails, the host is rolled back, and the error adds the provider's own fix to git's words (`RemoteWorkrooms.Place.credentialHint`). A local container workroom has no provider, so it keeps the Mac's `gh` relay (ADR 0039), which also rewrites ssh origins to https.

The costs are accepted:

- On boxd the credential is a `repo`-scoped OAuth token. It reaches every repository the user can, and it sits in `GH_TOKEN` in every process on the machine.
- On exe.dev the user sets up each repository once. The token never enters the VM.
- Workroom can no longer narrow or revoke a workroom's access itself. Revoking it is the provider's job, and is account-wide on boxd.
- A generic ssh host (#378) has no native integration: its git credentials will be whatever the user set up on it.
- Nothing migrates a remote workroom a Nightly or Dev build enrolled with the broker (no stable release did): its git config still names the agent's removed broker helper, so it is recreated rather than repaired.
