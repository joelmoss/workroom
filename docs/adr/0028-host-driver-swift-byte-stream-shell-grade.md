# A host driver is a Swift protocol over a byte stream, and every driver must authenticate its peer as strongly as a shell login

`HostDriver` is a Swift protocol in the Mac app, with `create`, `destroy`, `openStream` and `exec`. Its contract is "give me a bidirectional byte stream to wr-agent", not an ssh endpoint, so a provider that offers only an SDK exec call can still be a driver. Drivers shell out to a CLI the provider supplies, or to its ssh API, the way the app already shells out to `WorkroomCLI`: the boxd driver runs `boxd ... --json` and reads the ssh stanza and host key the CLI writes, because bypassing the CLI would mean reimplementing both. A Rust driver library and an ssh-only contract were rejected. The cost is that a driver cannot be shared with a non-Apple client. A stream that reaches wr-agent is a shell, because its exec service runs `git` with arbitrary arguments, which is arbitrary code execution. So ssh, an SDK exec call or a WebSocket must each authenticate its peer as strongly as a shell login before it counts as a driver.
