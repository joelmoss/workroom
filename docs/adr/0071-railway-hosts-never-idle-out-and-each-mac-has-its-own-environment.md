# A Railway host is created with its idle timeout off, each Mac keeps its hosts in its own environment of one Railway project, and the relay's host key is pinned on first use

Decided 2026-11-13 (Railway sandboxes design interview), accepted once the live spike of 2026-11-13 (branch `prototype/railway-sandbox-spike`, `vcs/scripts/railway-spike/FINDINGS.md`) confirmed the facts it rests on: a sandbox created with `idleTimeoutMinutes: 0` was still `RUNNING` 47 minutes later with no login ever made to it, `workroomd` kept running and answering after the ssh login that started it ended, and the relay presented the same host key on every connection.

A Railway sandbox has no sleep or stop state: an idle one is destroyed with its disk (30 minutes by default on Hobby and Pro, 5 on Trial and Free, where it cannot be turned off). Workroom creates every Railway host with `idleTimeoutMinutes: 0`, so a host lasts until its workroom is deleted, as an awake boxd host does, and paying for it is the user's concern, as [ADR 0017](0017-remote-workrooms-fresh-host-no-wakefulness.md) already treats wakefulness. The idle timeout is not a host option. Trial and Free accounts are refused at setup with the reason. A sandbox destroyed anyway (from Railway's dashboard, a failure, a downgraded plan) is shown gone through `HostPresenceReporting`, with Remove workroom as its only action, since its clone went with it.

Hosts live in a `Workroom` project the user creates or picks once, and each Mac has its own environment in it, made by setup and recorded by id in config (so a Mac moved with Migration Assistant keeps it; one rebuilt from scratch gets a new one). Release and Nightly share that environment, as they share config ([ADR 0036](0036-release-and-nightly-share-provider-hosts.md)); a Dev build has its own. A sandbox has no name, label or metadata, and `sandboxes` filters only on `active`, so the environment is the only thing that says which Mac made a host: the launch sweep destroys any sandbox in this Mac's environment that no host record names, which also catches a crash between `sandboxCreate` and recording its id. Amended 2026-11-14 (the pre-landing review of #623, owner decision D2): two Macs can still share one environment, when Migration Assistant or a Time Machine restore copies `placement.json`, and each would destroy the other's live hosts, which its own records can't name. So the sweep destroys only sandboxes in this Mac's own create ledger (`create-ledger.json` beside its Railway key, shared by Release and Nightly under a file lock): a create writes its intent there, with the time, before it calls `sandboxCreate`, fills in the sandbox's id when the reply arrives, and the entry goes once the host's record is written. An intent whose reply was lost is reconciled by listing the environment and taking the one sandbox nothing names that Railway made within a few minutes of the intent; when more than one could be it, none is destroyed. A sandbox the ledger doesn't account for is never destroyed. The residual risk is another Mac's create landing alone in that window just as this Mac's reply was lost. Railway's caps (10, 50 or 100 sandboxes and as many checkpoints) are per environment, so each Mac has its own, and a checkpoint is offered as a host image only on the Mac whose environment holds it.

Railway's ssh relay (`ssh.railway.com`, target `sbx:<environmentId>:<sandboxId>`, from the CLI's source, not its docs) does not publish its host key. The driver learns it at setup, pins it, and treats a changed key as a permanent refusal, as boxd's driver does; the `HostDriver` rule that a peer is checked as strongly as a shell login is met from the first use on. Railway is asked to publish the fingerprint.

Rejected: Workroom sending heartbeats. It brings back the wakefulness obligation ADR 0017 removed, and at one a minute per host it meets the API's limits (100 requests an hour on Free, 1,000 on Hobby). Rejected: disposable hosts that end after an idle timeout. A workroom would lose uncommitted work to a lunch break. Rejected: one shared environment. With no tag on a sandbox, no sweep could tell another Mac's host from an orphan of this one. Rejected: `accept-new` for the relay's key, which checks nothing.
