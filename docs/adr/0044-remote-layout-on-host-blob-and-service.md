# A remote workroom's pane layout lives on its host as an opaque blob behind a revision, served by a version-gated chunked JSON service

A remote workroom's pane layout (its tabs, splits and terminal counter) is stored on the host by `wr-agent` as bytes it never parses: one file per workroom in a `layouts` directory beside the screens directory, each with a revision. A put names the revision it read and is refused with the current one if that moved, checked and written under one lock. A blob with no tabs is an explicit closed layout, distinct from revision 0 for never written, so closed tabs do not come back. The app sanitises a blob it reads back, as it does `session.json`. Requests are JSON on the existing chunked envelope as `Service::Layout`, gated by protocol version 7 against the peer's raw hello version, with a 4 MiB blob cap equal to the app's whole `session.json` cap. An older `wr-agent` means a per-Mac restore, with nothing shown. Rejected: keeping only session metadata, which loses splits and non-terminal tabs; a live shared layout, which nothing in #255 needed; and Control frames, which need a hand-written binary codec and a cap near 1 MiB.
