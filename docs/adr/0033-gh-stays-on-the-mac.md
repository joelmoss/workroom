# GitHub status stays on the Mac's `gh`, and every probe names its repository instead of a working directory

Pull request and checks status, and pull request writes, for a remote workroom are not moved to wr-agent. They run `gh` on the Mac, as `gh pr ... --repo host/owner/name` or `gh api --hostname`, in a neutral directory, from a validated `GitHubRepository` identity that has no other constructor. Running `gh` on a host would need a GitHub API token there, and Workroom gives a provider's host only the broker's repository-narrowed git token (ADR 0024). A remote workroom also has no local checkout to run in. Naming the repository removes any dependence on a working directory by construction. A remote host's identity is registered with its location, and a host with a port is refused because `gh api --hostname` rejects one. Owner and name are interpolated into a GraphQL query, so validation is mandatory. A remote workroom shows no CI status yet, because CI is keyed to the branch-tip commit and nothing on the Mac can name one for a repository it has no checkout of. The cost is that a remote workroom's pull request badge depends on the Mac's `gh` login.
