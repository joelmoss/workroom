# ssh trust follows who owns the key, and no Mac ssh credential reaches a host

Where Workroom or the provider tool owns the key (the container driver and boxd), the driver writes its own `ssh_config`, passes it with `-F`, and pins the host's key out of band with `StrictHostKeyChecking yes` and `BatchMode yes`, so nothing can prompt. Where the user owns the key (exe.dev, and the planned generic ssh driver, #378), the driver runs the user's own ssh with only a few `-o` overrides and checks the host key against the user's `known_hosts` through `HostKeyAlias`. The owner asked for ssh as close as possible to normal usage, and a fingerprint built into the app would need an update after every rotation. The first exe.dev build chose a key itself and could pick the wrong account's. Under both policies no ssh agent is forwarded and no ssh credential from the Mac's environment reaches the host, because a forwarded agent dies with the laptop connection, exactly when remote workrooms matter. On a provider's host, git credentials come from the broker (ADR 0024); a container workroom on this Mac may take them from the Mac's `gh` through a relay (ADR 0039). The cost is two opposite ssh policies in one app.
