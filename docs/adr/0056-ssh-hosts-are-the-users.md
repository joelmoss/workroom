# An SSH host is the user's server: several workrooms per host, one agent, no system changes, and a delete removes only the workroom's folder

Decided 2026-10-22 (owner, triage of #378). Status: accepted, not yet built. Narrows [ADR 0017](0017-remote-workrooms-fresh-host-no-wakefulness.md) and [ADR 0040](0040-deleting-a-remote-workroom-is-app-only.md) for SSH hosts; both stand for every other driver.

An SSH host is a Linux server the user already has. Workroom never creates or destroys one. A create names the host as the user would after `ssh` (an alias from their config or `[user@]host`; ports and jump hosts come from their config), plus a parent folder that defaults to the one last used on that host (`~/workrooms` the first time), and makes `<folder>/<workroom name>` there. It refuses a folder that already exists, because the CLI keeps names unique per project only. One host holds any number of workrooms, served by one wr-agent per login user. Release and Nightly share it, as they share provider hosts (ADR 0036), and a Dev build keeps its own state folder so a work-in-progress agent never replaces the one real workrooms use. A delete runs the teardown script (ADR 0053), ends that workroom's sessions and removes only its folder. It never removes the folder the user typed. The host's shared state (port forwards, status watch, connection) goes only with its last workroom, and the agent is stopped then only if the agent itself reports no sessions, since another Mac may have terminals there. When the host can't be reached, the delete fails and keeps the workroom, and Delete Anyway drops it and names the folder left behind. Nothing is installed with root: no sudo, no systemd unit. The app starts the agent in the background on connect (`--idle-timeout never`, screens on disk), and starts it again after a reboot, so the agent gets the user's login `PATH`. ssh follows ADR 0029 for a user-owned key. A host with no `known_hosts` entry gets an in-app Trust prompt showing its fingerprint; a changed key is never trusted automatically; ssh that needs a password or passphrase prompt stops the create before anything is made. git uses the host's own credentials, never the Mac's `gh`, and the origin must still be on github.com (ADR 0041). Workrooms get port forwards as container workrooms do, loopback on the host only. No pending-host entry is ever written for an SSH host, so the launch sweep (ADR 0038) can never call destroy on the user's server.

Rejected: one host per workroom (people have one server); the typed path as the workroom's folder itself (a slip like `~` would be deleted); a hosts list in Settings; refusing an unknown host key and sending the user to Terminal; `systemctl --user` with lingering or root units (Workroom shouldn't install services on a server it doesn't own, and a supervisor's only extra, restarting the agent while the app is away, saves no sessions); relaying the Mac's `gh` (it dies when the laptop disconnects); one agent per workroom (isolation from a crash nobody has seen, for many more processes).
