# Screens are stored as VT bytes, never as snapshots, and libghostty-vt is pinned to the app's Ghostty revision

Whatever wr-agent writes to disk is VT bytes behind a small versioned header, never a libghostty-vt snapshot, because the snapshot format has no compatibility guarantee between revisions and a newer wr-agent may read an older one's file after a reboot (ADR 0009 does the same for hand-off). With `serve --screens` on durable disk, a host records each changed session every 2 seconds. After a reboot, an attach that asks only for an existing session (a restored pane) and names one wr-agent no longer holds is shown that last screen, frozen, with no pty and no new shell, because starting one silently would hide the loss. A late client on a live session is repainted from the shadow terminal (ADR 0010): the formatter with its extra flags on, then a hand-emitted cursor position and kitty keyboard flags, with the parser continuation last. libghostty-vt is built from the same Ghostty sha as the app's GhosttyKit, and the two pins are bumped together. The costs are an unfinished escape sequence lost across a reboot and a second Ghostty build, with Zig, inside a Rust crate.
